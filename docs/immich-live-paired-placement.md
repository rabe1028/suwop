# Immich Live Photo の配置変更と結果確認

この実装は Live Photo の静止画 P と付随動画 M を個別の物理資源として扱う。
一覧のグループ ID は送信先 ID に使わない。共有 M は一度だけ確認画面へ表示し、
関連する親を併記する。各資源の現在地・変更先・変更しない項目・アルバムへの影響を
確認した後、単一資産 PUT を順に実行する。

P の変更先は Timeline / Archive / Locked、M はこれらと Hidden を選択できる。
ここで Immich の Hidden は通常 Live Photo の付随動画を一覧外に置く配置であり、
Apple Photos の非表示や PIN による Locked と同じ意味ではない。
既存の関連グラフ契約と通常復帰先は P=Timeline（または Archive）、M=Hidden を
扱っている。IMAGE を Hidden にする表示・復帰契約と provider の受入れ証拠は
確立していないため、この実装は P の Hidden を明示的に拒否する。
これは任意の provider 配置の完全対応を示すものではない。

各 PUT の直前に、同じセッション・確認画面・期限・世代と安定版 3.3.3 の契約、
全資源の identity・関連・配置・アルバムを再確認する。表示と取得に使う native
consumer は全 P/M を同時に捕捉し、既存の取得・再生が終了した証拠を得てから送信する。
送信前の Unknown と結果を SQLite に保存し、各段階の状態を別々に確定する。
履歴の読込み、UI の応答、終了処理の成功は新しい書込み権限にはならない。

応答を失った Unknown は自動で再送しない。「現在を確認」は各資源の現在の観測を
記録し、過去の送信結果を成功へ変更しない。未送信の項目は、対象を明示して
「現在のまま終了」できる。この操作は写真を変更せず、元の実行カーソルを退役させる。
Unknown を含まない履歴の残りの未送信項目は、新しい全資源の変更先と確認を経て
別の intent に置き換えられる。既に終了した項目を再び置き換えることはできない。

通常の読取りセッションで P/M の identity・関連・現在の非 Locked 配置を改めて
確認できれば、PIN の再認証や 3.3.3 の書込み許可なしで表示と Live 再生へ戻せる。
過去の Unknown は維持する。表示専用の証拠は共有・編集・転送・削除・新しい配置変更を
許可しない。グリッドとプレビューは P の raster のみを専用の所有者で取得し、
Live 再生で初めて P/M 原本を取得・検証する。表示元が Apple Photos に切り替わった
グループでは、その Apple の表示経路を優先する。

取消・scene 失効・新しい capture は表示画像を同期的に消し、取得・再生の実際の
終了を待つ。終了を確認できない所有者は保持する。PhotoKit の終了待ちが期限切れになった
場合と unlink が失敗した場合に限り、PIN なしで終了処理だけを再試行できる。期限切れの
再試行は、同じ request 自身の終了 callback が後から届いたあとにだけ成功し、unlink は
1 回だけ行う。request ID が無効だった場合や callback が main queue 以外で届いた場合は、
終了 callback を証明する手段がない。この場合は再試行を出さず、原本と所有者をアプリの
終了まで保持し、それまで Live の読取りと再生も止めたままにする。
どちらの再試行も provider への変更操作や原本の再取得を再開しない。
