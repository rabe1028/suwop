# 写真の通常削除と復元

写真の保存先情報またはライブラリの複数選択から「Immich のゴミ箱に移す」を選ぶ。
確認には対象の名前・件数・接続先・現在の保持日数を表示する。
Apple Photos のコピーは変更しない。Move の記録を作成・変更する操作ではない。

コレクションまたは表示と操作メニューから「Immich の最近削除した項目」を開く。
サーバー上の本人のゴミ箱を全ページ取得し、単独・複数選択で同じ保存先へ復元できる。
一覧はページをまたいでサーバーの撮影日時降順を保持する。
取得した本人の削除済みIDは、同じImmichの通常一覧からも除く。Appleのコピー・他アカウント・転送履歴は保持する。
再起動後のキャッシュだけでは復元できず、一覧の更新と操作前の読み直しが必要。
パートナー共有の写真は除外し、本人の写真だけを表示・復元する。除外した行だけのページでも次のページを取得する。
完全な一覧を取得できない場合、欠落・重複・循環したページや本人の写真の不正な状態を確認した場合は操作を止める。

現在は Immich 3.2 以降の 3.x に対応する。
写真の検索・参照・削除と、`GET /config` のユーザー設定参照権限が必要。
通常削除は `DELETE /assets` の `force=false` を使用する。
ゴミ箱が無効、保持日数が0、設定を取得できない場合は開始しない。
確認後にも設定と写真を読み直し、保持日数・所有者・状態・識別情報・版が変わった場合は送信しない。
サーバーの保持設定はその後も変更され得るため、永久に復元できることは保証しない。

復元は選択した ID だけを `POST /trash/restore/assets` に送る。
件数応答だけで成功とせず、各 ID の所有者・削除状態と原本の識別情報を再取得して確認する。
原本の checksum・名前・種類・撮影ファイル日時・Live Photo の関連 ID を照合する。
これは API による状態確認であり、全ファイルのバイト列をダウンロードする検証ではない。
新しい日時・位置・お気に入りや編集データを上書きするリクエストは送らない。

送信前に専用の未確定操作記録を保存する。保存失敗なら送信しない。
応答紛失・停止・強制終了・読み直しの失敗・結果保存の失敗では記録が残り、対象の書き込みを止める。
同じ原本の Apple コピーからの Copy / Move も、現在接続した Immich の結果を確認するまで開始しない。
Apple の原本を新しく取得して照合し、転送の記録・アップロードを作る前に停止する。
「操作の結果を確認」は読み取りのみを行い、目的の状態と同じ原本だと確認できた時だけ記録を解除する。
反対の状態・別の所有者・別の原本・取得不可では解除も書き込みの再送もしない。
サーバーや別アプリで完全削除された場合は復元できない。

## Apple Photos の通常削除と復元案内

写真の保存先情報で「Apple Photos から削除」、複数選択で「選択した Apple 側のすべてのコピーを削除」を選ぶ。
同じ原本に Apple の複数のコピーがある場合は、その保存先の全コピーが対象になることと件数を表示する。
Rust が明示された Apple 保存先・重複しない ID・現在のフルアクセス・native の削除権限・版とリソース構成を確認する。
Move receipt は不要で、通常削除が転送履歴を作成・変更することはない。Immich のコピーは保持する。
写真の名前と件数、保存先、iCloud 写真が有効なら他の端末へも削除が反映されること、復元方法を確認に表示する。
確認後に対象を再取得し、原本をダウンロード・ハッシュ照合する。iCloud の原本では待機とダウンロードが必要な場合があり、削除開始前は停止できる。
原本の識別情報を含む専用意図記録を永続化できなければ、PhotoKit へ削除を要求しない。
PhotoKit の change queue 内でも、フルアクセス・正確な ID 集合・削除権限・版・構成を Rust で再検証してから削除する。
通常削除の条件は Move の条件とは独立し、native が許可する編集済み・Live・バーストの写真を Move の制約だけで拒否しない。共有アルバムの写真は対象外。

PhotoKit の明確な適用成功・適用失敗を別の enum として保存する。明確な失敗なら写真を残し、意図記録を完了する。
成功応答の保存後に記録の完了保存が失敗した場合は、再起動後に保存された応答から記録だけを完了できる。
応答の紛失・停止・結果保存の失敗・矛盾した native 応答では結果不明の記録を保持し、削除を自動再送しない。
対象の ID と既知の同じ原本のコピーに対する編集・日時／位置・お気に入り・アルバム変更や Copy／Move を止める。
転送前には新しく取得した原本のハッシュも照合する。無関係な写真・他の保存先・既存の転送履歴は書き換えない。

表示と操作メニューの「Apple Photos の削除と復元案内」で記録と案内を開く。
結果不明の「通常のライブラリで見えるか確認」は対象 ID を full access で読み取るだけで、削除は再送しない。
写真が見えないことは削除成功・「最近削除した項目」への所属・復元可能性の証拠にはならず、結果不明の記録を解除しない。
権限が拒否・限定・読取り中に変化した場合は有無を判断しない。
このアプリは公開 PhotoKit で「最近削除した項目」を一覧取得・復元する API を装わない。
復元は Apple Photos を開き、「コレクション」→「ユーティリティ」→「最近削除した項目」でロックを解除し、対象を選んで「復元」を行う。
Mac は写真アプリのサイドバーの「最近削除した項目」を開く。
保持期限や Photos の状態によって復元できない場合がある。iCloud で同期した削除・復元も他の端末へ反映される。
[Apple の公式手順](https://support.apple.com/en-us/104967)を確認する。

## 検証の範囲

検証は Rust の操作状態・故意の失敗・複数選択、実 Rust FFI、専用 Immich API CI、
simslim VRT の空・キャッシュ・未確定操作の画面を分けて行う。
生成JPEGの Apple 通常削除・OS確認取消・応答消失後の再起動は[専用 Native PhotoKit](native-photokit.md)で検証する。実機・iCloud・native 複数選択・Photos アプリでの実復元、実ライブラリでの操作はこれらの通過に含めない。
