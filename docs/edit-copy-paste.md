# 編集をコピー／ペースト

写真ビューアの編集メニューから「編集をコピー」を開き、実際の保存先とコピー項目を選ぶ。
調整値・フィルター・切り抜き／向きを個別に選べる。コピーした値はアプリ内に保存し、再起動後も次のコピーまで保持する。
保存後にコピー元を変更しても、コピーした値は変わらない。

単独の写真では現在の表示元を、ライブラリの複数選択では選んだ写真のApple側のすべての保存コピーを対象にする。
Apple側にない写真を含む選択は黙って飛ばさず停止する。確認画面に、書き込む写真名・件数・コピー元・項目を表示する。
一度に50枚まで。Photosの書込みは写真ごとで、全写真を一つの不可分な変更として保存するものではない。

Rustが写真の同一性・権限と一覧・既存編集・原本・出力形式を全対象で先に検査する。
保存直前にも既存編集と写真の世代を検証する。選ばなかった項目は保存先の値を保持し、同じ編集なら書込みを省略する。
切り抜きはEXIFの向きを適用した原本上の比率で拡大縮小する。左上は切り下げ、右下は切り上げて整数の範囲を検証する。
日時・位置情報・お気に入りと原本バイトを保存後に読み直す。SwiftはRustの保存計画をPhotoKitと既存のCore Image描画へ渡す。

各PhotoKit送信の前に、原本の署名・メタデータ・既存編集と予定した編集を永続化する。
応答の消失、出力の不一致、原本の変化、保存記録の失敗では、その時点で後続の貼り付けを停止する。
確認できた枚数とエラーを表示し、結果不明の写真の書込みを止める。確認できた写真は個別に記録を完了する。
作業ファイルのパスはこの記録に保存しない。

「編集のコピーと貼り付け結果」から一覧を更新して「貼り付け結果を確認」すると、書込みを再送せずに読む。
予定した編集・描画サイズと原本・メタデータが一致するか、送信前の写真の世代と編集が変わっていない場合だけ記録を完了する。
別の編集や原本の変化があれば結果不明の記録を保持する。ネイティブの編集セッションを閉じられなければ、使用中かもしれない作業ファイルを削除しない。

現在の対象は、Suwopで保存した既知の編集を持つApple静止画と、既知の編集または未編集のApple静止画への貼り付け。
既存のv1幾何編集も読める。他のアプリの編集を再現できない場合は、失わないために貼り付けを拒否する。
SDR・非透過・1,600万画素以内という現在の描画上限を引き継ぐ。動画・Live Photo・Immich編集は今後の対象。

[Appleの操作ガイド](https://support.apple.com/guide/iphone/edit-photos-and-videos-iphb08064d57/26/ios/26)も、項目を除外するコピーと複数写真への貼り付けを説明している。
Apple Photosの自動的なホワイトバランス・露出の合わせ込みは再現していない。Suwopではコピーした調整値をそのまま使う。

Rustは7通りの項目選択、異なるサイズと極端な比率、既存値の保持、全件事前確認、キャンセル、送信前の記録、
部分成功、応答消失、原本の変更、読み直しと書込み停止を検証する。
Swift実FFIでは選択項目の保存と確認・キャンセルを、simslimの固定Simulatorでは画面差分とコピー項目の実操作を検証する。
PhotoKitへの実保存・再起動・iCloud同期・実機とVoiceOverの受入れは別途必要。

ローカルの `make check` はRust 194／Swift 46 testsと全品質gateを通過した。
`make apple-build` はRust全5 target・XCFramework・iOS Simulator・macOS universal app buildsを通過した。
固定環境の `make vrt` は既存18枚の基準を保持した23画面の比較、2件のhostedテストと3件のXCUITestを通過。
コピーの選択操作では、行の中央ではなく実際のスイッチ本体をタップして値と確定結果を確認している。
記録と比較の成果物は `DerivedData/VRTArtifacts/20261012T231608Z-33186/` に残す。失敗した初回の操作テストを通過の証拠に数えない。
