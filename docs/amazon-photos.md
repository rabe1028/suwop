# Amazon Photos（日本）

日本のAmazonアカウントを、アプリ内の専用ブラウザでログインして接続する。
非公式APIなので、Amazon側の変更やセッション期限切れでは再ログインが必要になる。
Cookieは端末のKeychainに保存し、Rust・保存カタログ・ログには渡さない。

## 対応する操作

- 写真・動画の一覧、サムネイルとプレビュー、名前・日付検索。
- 原本のダウンロード、共有、Apple Photos / Immichとの双方向コピー。
- 未照合原本の照合。AmazonのMD5・サイズと取得した原本を照合し、SHA-1とSHA-256を計算する。
- お気に入りの更新と直後の読戻し。

アルバム編集、日時・位置情報の書換え、現在の編集画像の共有、保護写真の閲覧、
Amazonを含むMoveと削除、Amazonの写真の意味検索（画像解析）は未対応。
Amazonの写真は解析の対象に入れないため、解析を止めることもない。原本コピーでは転送元を削除しない。
一覧は非公式APIのページ上限（9,999件）で未完了になる場合があり、完全取得と扱わない。
一覧の更新中は件数の表示だけを出し、取得した写真は更新全体の確定後にまとめて表示する。
接続済みで一覧を取得できていない間は「取得不可」の空の一覧として扱い、
Apple / Immichだけにある写真とは表示しない。

## 原本と形式の扱い

受け付けない形式は**変換せず転送を止める**。理由と、Apple Photos / Immichを保存先に
選ぶ案内を表示する。複数ファイルは最初のアップロード前に全件を確認する。
Live Photoの動画や補助データは、組としての保持を確認できないため停止する。
JPEG / PNG / HEICなどの画像、対応候補のRAW、MP4 / MOVなどの動画を拡張子で事前確認する。
RAWや動画の各変種が実際に受け付けられるかは、Amazonの応答で最終判断する。
禁止文字・予約名・末尾の空白などのファイル名制限も確認する。

対応候補の一覧は `crates/suwop-core/src/amazon/formats.rs` に置く。
根拠は[Amazonの対応形式・名前制限](https://digprjsurvey.amazon.co.uk/csad/help/node/GGU2SU8Y22DZYRMQ)。
この資料には英国向けの情報を含み、日本アカウントの全形式の実測保証ではない。

## 書込みと復旧

送信前にコピーの開始記録と原本のSHA-256・サイズ・MD5を永続化する。
アップロード後は保存先の原本を再取得し、実際のSHA-256が一致した場合だけ検証済みとする。
ログイン期限切れ・通信断・不明な結果では、自動で書込みを再送しない。
アクセスの取消しと実際のネットワーク送信の間も、ネイティブの送信ゲートで確認する。
送信前の記録を保存できない場合は送信せず、その記録をメモリにも残さない。

アップロードはネイティブが `URLSession` のタスクを開始する直前に送信済みの印を付け、
`AmazonUploadSubmission` として送信の有無をRustへ返す。
「未送信」の判定は同じロックで確定させ、確定後に遅れて届いた送信処理はタスクを開始せず取り消す。
開始を試みた後は、取消しと競合した場合も送信済みとして扱う。
送信前に止まったことの証明（印がない）と、HTTP 400 / 413 / 415 の明示的な拒否だけを
「保存されていない」と扱い、その試行の記録だけを削除して保存する。この削除を保存できない場合は記録を残す。
送信後の通信エラー・取消し、その他のHTTP状態（409、429、5xxなど）、IDのない成功応答、
不整合な送信結果、送信後のアクセス変更は未確定として残す。
一覧に見つからないことは遅れて届くPOSTがないことの証明にならないため、未確定記録を消す操作は設けない。

成功応答の写真IDは、形式を確認したうえで読戻しの前に記録へ保存する。
読戻しが一時的に失敗しても、このIDで後から照合でき、一覧の検索は不要になる。

接続設定の「未確定アップロードの結果を確認」ではGETのみを行う。
読むのはAmazon側の保存先だけで、転送元の原本は読まない。転送元がその後に削除・非表示になっていても照合できる。
一覧の検索は内容を含まないメタデータの読出しで、カタログ更新と同じく現在の接続とアクセス世代に限る。
原本の取得は記録した1件の写真IDだけに限り、保存先の写真が保護・拒否されている場合は読まずに未確定のまま残す。
応答で写真IDを取得できなかった場合は一覧を検索し、MD5・サイズで候補が一意に決まり、
取得した原本のSHA-256も一致した場合だけ記録を検証済みにする。
候補がない・複数ある・ページ上限に達する場合は未確定のまま残し、新たなAmazonアップロードを止める。
別の保存先へのコピーは選択できる。写真の削除・再送によって曖昧さを解消しない。
この照合は保存先に同じバイト列が実在することの確認で、新しい写真を作成したことの証明ではない。
以前からある同一内容の写真が一意に一致した場合も検証済みになるが、コピー記録は「コピー中」のまま
完了扱いにせず、Moveや削除の根拠にもしない。
保護した写真を含む転送記録は、そのアップロード記録ごと表示から除く（端末内の記録と書込みの停止は保持する）。

アップロード前に日本のアカウントAPIから `uploadServiceUrl` を読み、
HTTPSの `upload-photos.amazon.co.jp` と既知のパスだけを受け付ける。
地域名からAWSのホストを推測しない。Cookieは通常のドメイン・パス制限に従って送る。
ダウンロードの転送先はRustが都度検査し、CDNにはCookieを送らない。
TLS検証の無効化や自動リトライは使わない。

## 検証の区分

`crates/suwop-core/tests/suite/amazon.rs` は契約フィクスチャであり、実サービスの成功を意味しない。
`Tests/SuwopShellTests/AmazonTransportTests.swift` は送信停止・転送先処理・FFIハッシュ境界を確認する。

従来の独立した読取専用PoCでは、日本アカウントの一覧、表示したプレビュー、DNG原本、
MD5・サイズと取得後のメタデータ再確認が成功している。
2026-10-23には本体のネイティブ経路でも、日本アカウントへの合成PNG1枚のアップロード、
原本読戻しのMD5・サイズ・SHA-256一致、お気に入りの追加・解除、プレビュー復号を確認した。
Apple側の原本取得とコピー記録の保存には下記のフィクスチャを使っており、PhotoKitの実機実測とは区別する。
必要なローカル検証は `make check`、`make apple-build`、`make vrt`。
実アカウント・PhotoKit・CIの結果は、それぞれ分けて報告する。

実アカウントの追加検証にはMacの `SuwopAmazonMac` テストスキームを使う。
通常はスキップし、明示的に `SUWOP_AMAZON_LIVE=1` と
`SUWOP_AMAZON_EVIDENCE_DIR`（証拠を保存する専用ディレクトリ）を指定した場合だけ動く。
先に、そのテストホストと同じSuwop本体で日本のAmazonアカウントにログインする。
ログインで認証が保存されても接続設定が未保存の場合は、一意に特定できる保存済み認証を使い、
本体のRust・ネイティブI/Oを通して接続を本番SQLiteへ保存してから進む。
この明示的な検証中は通常UIの起動時更新を止め、別の状態で本番保存を上書きしない。
合成PNGのApple側の一覧・エクスポートと、状態の読込み・保存・作業ディレクトリをフィクスチャで代替する。
状態と転送記録は証拠ディレクトリの独立したJSONへ保存し、本番SQLiteへの保存を実測したとは扱わない。
Rustのコピー処理、本体のKeychain・HTTP、送信前の記録、原本読戻し、お気に入りの追加・解除、
プレビューのネイティブ復号を通す。
利用者の写真は書き換えず、検証用PNGはAmazon上に残す。PhotoKitの実機検証とは区別する。

接続設定は、開いただけで既存のImmichキーを読み出さない。
明示的な読込み、起動時の認証復元、Amazon通信時のCookie読込みでは、ネイティブKeychainの返答待ちを制限する。
OS側で認証処理が継続しても、期限後の戻値を新しい接続に流用しない。
Amazonのログイン完了時に別の更新処理が動いていても、接続要求を保持し、更新後に優先して実行する。
接続の確認または接続設定の保存に失敗した場合、その試行で保存した新しい認証は
Keychainから削除する（現在の接続で使っている認証は削除しない）。この場合はログインからやり直す。
「保存済みのAmazon認証で再接続」は、接続処理の前にアプリが終了した場合などの再試行に使う。
接続設定を保存した後の一覧更新の失敗では、新しい認証を削除しない。
Keychainに保存されたAmazon認証が複数ある場合は勝手に選ばず、ログインから接続し直すよう案内する。
