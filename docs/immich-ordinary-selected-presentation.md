# 外部で解除された選択原本の表示専用プレビュー

## 動作

PINで検証したImmich写真を外部でtimelineまたはarchiveへ戻した後、利用者が通常一覧を更新すると、最新の同一原本を確認できるIMAGEだけを表示専用として一覧へ戻す。過去の変更結果がUnknownでも、その記録を成功へ書き換えない。通常一覧へ戻ることと、原本の操作権限を得ることは別である。

Rustは過去のselectedObservation、原本の識別情報、通常APIで得た最新の所有者・checksum・revision・可視性・既知の関連グラフを照合する。異なる原本、不明な情報、VIDEO、変更された関連動画を、独立した静止画と推定しない。関連する動画の取得へは展開しない。読み取りのためにPIN再認証や3.3.3の書込み許可を要求しない。

得られる権限は一時的な静止画の表示だけで、共有、編集、お気に入り変更、再生、アルバム変更、archive、PIN変更、転送、削除を許可しない。既存の操作用キー一覧はRustの肯定的な判定を維持する。同じ写真に独立したApple Photos原本があれば、その表示元の操作は引き続き使える。

## 表示までの検証

表示専用のproof、要求、scene、世代を通常操作と分ける。取得前のmetadata確認、非公開のnative画像取得、取得後のmetadata確認、非表示の公開準備、最終metadataと現在のproofの照合を通過して初めて描画する。古いキュー内の要求を現在の要求として採用しない。public stateに画像の認証情報や取得用URLを公開しない。

表示元、アカウント、セキュリティ状態、sceneの終了・背景移行、再読み込みで失効した画像は描画できなくなる。キャンセルに従わない遅延取得も、最終承認された画像として復帰させない。同じキーの取得失敗はそのproofを破棄し、無関係なキーとsceneの現在の画像を残す。

表示専用のproofだけが失われ、private revisionと表示世代が変わらず、操作可能なキーが失われていない場合は、専用画像とthumbnailを失効させる。無関係な原本の操作確認を全体取消しない。通常原本の喪失、権限変更、アカウント変更などの全体取消は維持する。失効後に古い操作contextを取り直して有効化することはない。

proofや画像承認は保存しない。再起動後は明示的な再検証が必要で、schema8の変更履歴・witness・outcomeを表示の都合で書き換えない。要求の再利用と並行保持には上限を設け、同じ表示枠の置換と無関係な表示枠の保持を区別する。

## UI

通常の写真ビューアに表示専用の案内を出し、共有・編集・再生・お気に入り操作を無効にする。拡大、移動、表示元の切替、閉じる操作は利用できる。原本情報や履歴にある操作もRustの権限を越えない。Apple Photosへ表示元を切り替えた場合の操作は、その原本の権限に従う。

画像の取得・承認が拒否された場合は、読み込み表示を無期限に続けず、状態を確認して選び直す案内を出す。大きな文字では実ウインドウの文字サイズで操作の折返しと閉じるボタンへの到達を検証する。

## 検証の区分

- Rustは識別・権限・失効・競合・要求再利用・上限・転送再開時の拒否を検証する。
- 実Immich 3.2.4／3.3.3では外部解除後の明示更新、実derivativeの取得、前後の変更履歴の一致、関連原本の保持、取得各段階でのmetadata変更による拒否を検証する。derivative fixtureはJPEGと実測WebPの厳密なヘッダー境界を扱い、壊れた形式と切断を拒否する。これはnative画素描画の証拠とは分ける。
- Simulator nativeテストは最終承認、scene失効、遅延取得、要求再利用拒否、2原本間の独立性、および実際の通常原本喪失による操作contextの取消を検証する。
- UIテストは実ビューアの表示、通常文字／大きな文字、Apple原本への切替、取得失敗時の案内を確認する。48枚の既存基準画像は変更しない。

最終コマンド結果とCIはPR・実装ロードマップに記録する。この契約はPIN付きVIDEO／Live Photo再生や変更、実機／iCloud、実時間のPIN期限を完了したことを示さない。それらは別の受入れ項目として残る。
