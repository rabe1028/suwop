# PP03–PP07: 取り込み、複製、共有、メタデータ、コレクション

この変更はRust / Cruxで保存先の権限・構成・永続状態・再取得を判断し、Swiftでファイル選択、PhotoKit、AVFoundation、MapKit、共有先の入出力を実行する。検証結果は下記に記録し、実装だけを完了証拠にしない。

## 操作と保存先の違い

- 外部取り込みは、私有領域へコピーして検査したファイルを対象にする。ファイル名だけでRAW＋JPEGを自動結合しない。Live Photoは静止画と動画の識別子を照合する。送信前に記録を保存し、応答不明・再起動では自動再送しない。
- 複製は選択した一つの物理的な表示元から原本または現在の内容を取得する。元の写真や編集履歴を変更しない。Immichが既存IDを返した場合は「既に存在」と表示し、新規複製成功にしない。既存写真へメタデータや関連付けを書き込まない。
- 現在の内容の複数共有は全件の取得・検証が成功してから共有先を開く。同名ファイルも別ディレクトリに保存する。対応を確認できない編集を原本へ黙って置き換えない。位置情報を除く書き出しは新しい出力と許可したメタデータだけを使う。
- 共有作業領域はプロセスのカーネルロックで保護する。共有先が利用中のファイルを消さず、プロセス終了後に残った領域だけを次の起動で回収する。
- 日時はIANAタイムゾーンで指定し、夏時間の欠落時刻を拒否し、重複時刻を明示選択する。地名検索・地図選択・座標入力は同じRust検証を通る。取り消し・元の値への復元は各写真の値を個別に保持する。結果不明の操作は再取得し、自動再書込みしない。
- Apple Photosの説明は公開PhotoKit APIでシステムのキャプションを書き換えられないため、Suwop内の説明として保存・検索する。Immichの説明は保存先に書き込み、再取得する。
- Appleのフォルダーと通常アルバムの順序は、直前の階層・順序・権限を照合して更新する。共有・スマートアルバムは読み取りと制限の表示に対応する。Immichでは保存先が提供する日時順を使い、フォルダー・任意順・共有管理など非対応の操作には保存先での代替を示す。コレクション削除は写真原本の削除を意味しない。

Immichの書込み後はsidecar処理でrevisionが遅れて変わるため、読出しだけで連続安定を確認してから記録を確定する。指定外のメタデータや原本の変化、読出し失敗、上限まで安定しない場合は結果不明を保持する。安定観測は将来の変更が起きない保証ではなく、取り消しや次の書込みでも保存済みrevisionを含めて再照合する。

日時で要求したIANA名は操作記録のeditに残し、保存先の実値はafter.values.timeZoneに残す。一般の地域等価判定は指定瞬間の固定offset一致だけを認め、異なるIANA名を同一視しない。Immich日時操作の完了条件は地域名の保存ではなく要求instantの保存であり、後述のprovider観測zoneとは分けて検証する。取り消しは観測済みの地域表現から元instantを再構成する。

### Immichの位置変更とタイムゾーン表示

Immich 3.3.3は位置のsidecar書き込み後、GPSからタイムゾーン表示を再計算する場合がある。同一PUTに元の日時・offsetを補完しても防止できないことを生成fixtureで確認したため、位置操作は指定座標と絶対撮影時刻の保持を保証対象とし、タイムゾーンは要求値ではなく保存先の観測値として前後を記録する。入力画面と履歴はこの挙動を明示する。取り消しは位置を戻す操作であり、以前のタイムゾーン表示の復元は保証しない。

Immichの日時・位置操作に限り、有効なIANA名または厳密なUTC offsetの観測変化を許す。撮影瞬間・説明・原本・他の項目の変化は拒否する。保存先による再計算と、同じ短い観測期間中の外部timezone変更をAPIから区別することはできない。観測後のrevisionは厳密に保持し、次の操作・取り消し前には完全一致を要求する。日時操作では入力した地域でのlocal日時→絶対instant変換を厳密に行い、要求地域はjournal editへ保持する。Immichの観測timezoneはGPS由来の別IANAにもなり得るため、要求地域名の保存成功とは主張しない。合法な観測zoneのみを別表示し、絶対instantと他項目は厳密に検証する。日時Undoも絶対instantの復元であり過去の保存先zone表示は保証しない。

Immich 3.3.3の公開UpdateAsset DTOでは緯度・経度はoptional numberでありnullableではないため、GPSなしへの復元は非対応として送信前に拒否する。変更履歴はRustの復元計画と共通の判定で理由を表示し、取り消し・最初の値への復元をそれぞれ無効にする。元GPSがある位置の復元は実サーバーで検証する。元タイムゾーン不明の日時復元もUTC等を捏造せず拒否する。

元GPSがNew Yorkの生成fixtureでは、日時入力Asia/Tokyoがqueue完了後America/New_York表示となる一方、指定instantは厳密に保持されることを確認した。固定offsetの観測に限らずこの保存先仕様を日時操作にも適用する。入力画面と履歴に要求地域/観測zoneの区別を表示する。Appleのアプリ内地域記録および一般の厳密matches契約は変更しない。
